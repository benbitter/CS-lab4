SQL Injection: Authentication Bypass

Local-only educational demo: compare a deliberately vulnerable login with a parameterized login.

Authorized testing only. This demo listens on localhost. Do not expose it to a network or use these techniques on real services.

1. Vulnerable login

The server concatenates your input into the SQL query. Try the demonstration payload below in the username field.

2. Secured login

The server uses a parameterized query. The same payload should be treated as ordinary text and fail.

Demonstration steps

  1. First test a normal login: username admin, password ClassroomDemo123!.
  2. In the vulnerable form, enter this in the username field: ' OR '1'='1' -- . Enter any password.
  3. Repeat the same input in the secured form. It should fail.
  4. Watch the terminal to compare the vulnerable SQL string with the secure query using placeholders.

Important: The password is stored in plaintext only to keep this small classroom example easy to inspect. Real applications must hash passwords (for example with Argon2id or bcrypt), use parameterized queries, rate-limit login attempts, and protect sessions.
